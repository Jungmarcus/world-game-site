What is being checked, exactly
    
    
      
  1. Seal — the snapshot's SHA-256 fingerprint is recomputed from the file's own bytes over {schema_version:"2.0", date, source, countries_count, markets, countries} in that key order and must equal the fingerprint stored in the file.
    2. 
      
  2. Match — the signed statement names that exact fingerprint, date, source, country count and market prices.
    3. 
      
  3. Key — signing.json's key_id is the first 16 hex of SHA-256 over its own public key, and the sidecar names the same key.
    4. 
      
  4. Signature — the Ed25519 signature over the canonical statement (keys sorted at every level, no whitespace, UTF-8) verifies with that public key.
    5. 
    

    
A VALID result proves origin and integrity. It does not prove the data inside is true or current. Command-line equivalent: node verify-snapshot.js snapshot.json snapshot.sig.json signing.json (one file, needs only Node 18+). WebCrypto Ed25519 needs Chrome 137+, Safari 17+ or Firefox 130+; older browsers get an honest "cannot verify here" and the command-line route.
